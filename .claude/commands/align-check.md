# /align-check — 设定大纲对齐巡检

你的任务：对当前小说设定库做一次**对齐巡检**，回答"设定与大纲是否一致、有无缺漏、哪些需要补充"。这不是创作任务，而是审视任务。

严格分三阶段执行，**每阶段结束必须停下等用户确认**，不得一口气跑完。

## 参数解析

- `$1` = **scope**（缺省 `all`）
  - `all`：全库扫描
  - `arc:<文件名>`：只检查该大纲及其引用链（例：`arc:arc-总纲草稿`）
  - `char:<角色名>`：只检查该角色及其引用链（例：`char:伊利安`）
  - `world:<子域>`：只检查世界观子域（`magic` / `religion` / `geography` / `history` / `culture` / `politics`）
- `$2` = **depth**（缺省 `full`）
  - `quick`：只跑维度 1、4（死链 + 索引同步）
  - `full`：七维度全查

若参数无法识别，直接报错并列出可选值，不得静默推进。

## 阶段 ① 侦察（只读）

目标：根据 scope 把相关文件全部读进上下文。

**统一前置步骤**（所有 scope 都要做）：
1. Read `00-INDEX/_MASTER-INDEX.md`
2. Read `.claude/skills/worldbuilding/SKILL.md`（拿 10 条硬限制清单）
3. Read 用户 memory 中的 `feedback_naming_gods.md`、`feedback_narrative_layering.md`（两条硬规则）

**按 scope 继续**：

| scope | 额外必读 |
|---|---|
| `all` | 所有 `_index.md` + 全部 arc-* / char-* + 所有 _TEMPLATES/tpl-*.md |
| `arc:X` | `05-PLOT/X.md` + 该 arc 中出现的每个 `[[wikilink]]` 目标文件 |
| `char:X` | `02-CHARACTERS/char-X.md` + 其 `related/allies/enemies/faction/location/arc` 字段指向的每个文件 |
| `world:D` | `01-WORLD/D/_index.md` + 该子域所有文件 |

读取策略：
- **用 Glob 先列清单，再用并行 Read 批量读**，不要一条条串行
- 单文件超 500 行要注意（维度 7 会用到）
- 侦察阶段**不得**产出建议，只内化信息

侦察完成后，给用户一行简短汇报："已读取 N 个文件，进入报告阶段"，然后直接进入阶段 ②。

## 阶段 ② 报告（只输出，不修改）

按以下七维度产出报告。depth=quick 只做 1、4。

### 维度 1 · 引用存在性（死链）
- 对所有扫描到的 `[[wikilink]]`，Glob 验证目标文件是否存在
- 找不到的列为"死链"——**阻塞级 🔴**

### 维度 2 · 反向孤立
- 列出**没有被任何 arc/char/geo/fac/_index 引用**的设定文件
- 可能是草稿残留或真正孤立——**提示级 🟢**（不急着改）

### 维度 3 · Frontmatter 完整度
- 对照 `_TEMPLATES/tpl-*.md` 的字段清单核对
- 缺少 `summary` / `type` / `related` 等必备字段——**建议级 🟡**
- 缺少 `role` / `status` / `arc`（角色）或 `alignment` / `law_domains`（神明）等专用字段——**建议级 🟡**

### 维度 4 · _index.md 清单同步
- Glob 该子域实际文件 vs `_index.md` 文件清单表做 diff
- 漏列或多列——**阻塞级 🔴**（索引失真直接影响后续检索）

### 维度 5 · 大纲 ↔ 角色一致性
- arc 文件提及的每个角色，check `char-*.md` 的 `arc` 字段是否回链——**建议级 🟡**
- **特别**：`arc-伊利安-弧线.md` 中标记为**已确认但未揭露**或仍处于**参考设计**的内容，不应直接写进 `char-伊利安.md` 的当前主档正文（这是当前的分层口径）——**阻塞级 🔴**

### 维度 6 · 硬限制巡检
对照 `worldbuilding/SKILL.md` 末尾 10 条硬限制扫描：
1. 法则先在 / 2. 无创世神 / 3. 信仰不造法则 / 4. 邪神内源 / 5. 灵魂承载力硬限制 / 6. 加护卡不叠魔法卡 / 7. 幻兽卡不可转让 / 8. 真红不可复制 / 9. 降临协议 / 10. 神明命名格式

任何违反——**阻塞级 🔴**

### 维度 7 · 命名与风格
- 神明文件必须走「职能之神·专有名字」格式（例「丰饶之神·伊瑟拉」而非只写「伊瑟拉」）——**阻塞级 🔴**
- 命名对照 `07-REFERENCES/naming-规则.md`——**建议级 🟡**
- 单文件超 500 行——**建议级 🟡**（需拆分）

## 阶段 ③ 修改（分批确认）

**只在用户明确确认后进入**。

修改规则：

1. **先查后写**：每条修改前先 Read 目标文件当前内容，不得凭报告摘要修改
2. **最小改动**：只动本次报告涉及的行；不顺手重排、不"优化"无关内容
3. **双向更新**：修改 A 引用 B，则 B 的反向引用（related / allies / arc 等）也要同步——参考 worldbuilding skill 第五步
4. **分批停下**：
   - 阻塞级修完 → 报告 "🔴 已处理 X 条，请确认继续" → 停
   - 建议级修完 → 报告 "🟡 已处理 Y 条，请确认继续" → 停
5. **不创造不存在的设定**：若报告要求新建某个 fac/geo/char 文件，本命令**只创建骨架**（frontmatter + 空章节 + TODO 注释），真正的内容填写交给 `worldbuilding` skill
6. **硬规则不得违反**：
   - 神明命名必须是「职能之神·专有名字」
- char 卡记录当前已确认正史；未揭露真相与参考设计内容不回填
   - worldbuilding/SKILL.md 的 10 条硬限制

每批修改完后给出简表：

```
### 修改批次 #N（🔴 阻塞级）
- ✅ char-伊利安.md：移除死链 [[fac-巡游学院议会]]
- ✅ religion/_index.md：补录 2 个神明个档
- ⏸️ fac-X.md：按建议新建骨架（内容待后续 /worldbuilding 填写）

请确认是否继续处理 🟡 建议级。
```
